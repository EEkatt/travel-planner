# Definition Of Done

## Status

Draft

## For Analytics Documents

Документ готов, если:

- есть цель документа;
- заполнены ключевые разделы;
- открытые вопросы вынесены явно;
- выводы не противоречат другим документам;
- важные решения отражены в decisions.

## For Requirements

Требование готово, если:

- понятно, кто пользователь;
- понятно, какую проблему или пользовательскую ценность решает требование;
- есть приоритет `Must`, `Should`, `Could` или `Later`;
- есть критерий проверки или ссылка на acceptance criteria;
- требование можно проверить без знания внутренней архитектуры;
- MVP-требование не обещает функциональность outside MVP;
- нет блокирующих вопросов.

## For MVP Feature

Фича входит в MVP, если:

- она нужна для реального использования приложения в первой поездке;
- без нее MVP теряет основную ценность;
- она связана с явной пользовательской ценностью;
- ее можно реализовать без чрезмерного усложнения;
- она проверяема через acceptance criteria;
- она не является LLM, route optimization, live flight tracking, collaboration, booking, automatic import или full offline maps.

## For Backlog Item

Задача готова к реализации, если:

- указаны epic, priority и пользовательская ценность или связанное требование;
- есть проверяемые acceptance criteria;
- границы MVP/Later понятны;
- задача не содержит скрытого расширения MVP;
- зависимости и открытые решения вынесены отдельно.

## For Research

Исследование готово, если:

- указаны источники;
- выводы отделены от предположений;
- есть сравнение с проектом;
- есть рекомендация: взять в MVP, отложить или игнорировать.
