# Project Principles

## Status

Draft

## Product Principles

- Mobile first.
- Trip as a single source of truth.
- Customization over rigid booking flows.
- Manual input first, automation later.
- LLM as assistant, not as core dependency.
- Useful in a real trip before it becomes a large product.

## Engineering Principles

- Keep architecture simple until MVP is validated.
- Avoid vendor lock-in where possible.
- Protect personal travel data.
- Design data model for future sharing, but do not build collaboration in MVP.
- Prefer small, testable iterations.

## Agent Principles

- Agents propose, owner decides.
- If unsure, ask instead of silently changing direction.
- Keep open questions visible.
- Do not edit code from research-only roles.
- Important decisions must be logged.
