# Requirements

## Status

Draft

## Priority Scale

- `Must` - required for MVP.
- `Should` - valuable for the first release if it does not block Must scope.
- `Could` - useful after MVP validation.
- `Later` - explicitly outside MVP.

## Functional Requirements

| ID | Requirement | Priority | User value | Acceptance criteria | Status |
| --- | --- | --- | --- | --- | --- |
| FR-001 | Пользователь может создать поездку с названием и датами, если даты известны. | Must | Есть контейнер для всех данных путешествия. | Поездка сохраняется с названием; даты можно указать или оставить неизвестными; после сохранения поездка открывается с пустыми разделами плана, карты и деталей. | Draft |
| FR-002 | Пользователь может открыть основную структуру поездки как мобильный экран `Сегодня / Дни / Карта`. | Must | Во время подготовки и поездки пользователь не ищет данные по разным местам. | На экране поездки доступны вкладки или равнозначные разделы `Сегодня`, `Дни`, `Карта`; пользователь может перейти между ними без потери введенных данных. | Draft |
| FR-003 | Пользователь может добавить место через поиск. | Must | Можно собрать идеи и места из внешних источников в одну поездку. | При вводе названия показываются результаты; выбранное место сохраняется в поездку; сохраненное место отображается в списке мест и на карте, если у него есть координаты. | Draft |
| FR-004 | Пользователь может добавить место вручную текстом, если поиска недостаточно или нет сети. | Must | Пользователь не теряет идею места из-за слабого интернета или неполной базы поиска. | Пользователь может сохранить название; адрес или комментарий можно добавить текстом; место без координат видно в плане и помечено как требующее уточнения для карты. | Draft |
| FR-005 | Пользователь может видеть общую карту мест поездки. | Must | Пользователь понимает географический контекст поездки. | Карта показывает все сохраненные места с координатами; выбор точки открывает детали места; места без координат не ломают отображение карты и остаются доступны списком. | Draft |
| FR-006 | Пользователь может открыть место или адрес во внешнем картографическом приложении. | Must | Пользователь получает навигацию без ожидания собственной маршрутизации в продукте. | Для места или жилья с адресом/координатами доступно действие открытия во внешних картах; если данных недостаточно, приложение сообщает, что навигация недоступна. | Draft |
| FR-007 | Пользователь может распределять места и ручные события по дням поездки. | Must | Пользователь понимает план каждого дня. | Пользователь может добавить пункт в день, удалить пункт из дня и изменить порядок пунктов; порядок сохраняется после повторного открытия поездки. | Draft |
| FR-008 | Пользователь может видеть план конкретного дня вместе с его точками на карте. | Must | Пользователь сопоставляет расписание дня и географию без отдельного сервиса. | Экран дня показывает упорядоченный список пунктов; карта или компактный картографический блок показывает точки дня с координатами; отсутствие координат у части пунктов не скрывает список дня. | Draft |
| FR-009 | Во время дат поездки пользователь может быстро открыть текущий или ближайший релевантный день. | Must | В дороге пользователь сразу видит, что делать сейчас. | Если текущая дата входит в даты поездки, раздел `Сегодня` показывает текущий день; если даты отсутствуют или текущего дня нет в плане, пользователь видит понятное пустое состояние и может выбрать день вручную. | Draft |
| FR-010 | В разделе текущего дня пользователь видит ближайший следующий пункт, если он может быть определен. | Must | Пользователь быстрее понимает следующий практический шаг. | Если у пунктов дня есть время, ближайший будущий пункт выделен; если времени нет, приложение не делает ложный вывод и показывает ручной порядок дня. | Draft |
| FR-011 | Пользователь может вручную добавить рейс со стабильными полями: номер рейса, дата, время, аэропорты, терминал/гейт как текст, номер брони и заметки. | Must | Билеты из любого источника можно сохранить в поездке. | Рейс можно сохранить без автозаполнения; номер рейса, дата/время и аэропорты доступны в деталях; терминал/гейт, номер брони и заметки необязательны и сохраняются как введенный текст. | Draft |
| FR-012 | Пользователь может вручную добавить жилье со стабильными полями: название, адрес, даты, номер брони, контакты и заметки. | Must | Информация о проживании быстро находится во время поездки. | Жилье можно сохранить с названием или адресом; даты, номер брони, контакты и заметки необязательны; жилье отображается в деталях поездки и доступно из быстрого доступа. | Draft |
| FR-013 | Пользователь может хранить несколько объектов жилья в одной поездке. | Must | Поездки с несколькими городами или переездами поддерживаются без обходных заметок. | В одной поездке можно создать больше одного объекта жилья; каждый объект сохраняет свои даты, адрес и заметки; список жилья не объединяет разные брони. | Draft |
| FR-014 | Пользователь может добавлять заметки на уровне поездки, дня или объекта. | Must | Важные детали находятся рядом с контекстом, к которому относятся. | Заметку можно создать, открыть, изменить и удалить; заметка отображается в выбранном контексте; заметки поездки доступны из быстрого доступа. | Draft |
| FR-015 | Пользователь может создавать простые чеклисты. | Should | Пользователь не забывает вещи и действия перед поездкой. | Чеклист можно создать; пункты можно добавить, отметить выполненными, снять отметку и удалить; состояние пунктов сохраняется. | Draft |
| FR-016 | Пользователь может быстро открыть жилье, рейсы и заметки с основного экрана поездки; чеклисты доступны так же быстро, если они включены в первый релиз. | Must | В дороге пользователь не тратит время на поиск критичной информации. | С основного экрана поездки до списка или ближайшей релевантной карточки жилья, рейсов и заметок можно добраться одним действием; если чеклисты отложены, интерфейс не показывает сломанную точку входа. | Draft |
| FR-017 | Пользователь может быстро вручную изменить план во время поездки. | Must | Реальные планы меняются на месте, и пользователь сохраняет актуальный план. | Из экрана дня можно изменить время, заметку или порядок пункта; можно добавить ручной пункт; после сохранения пользователь возвращается к плану дня. | Draft |
| FR-018 | Приложение показывает сохраненные детали текущей поездки при слабом интернете или без сети. | Must | Пользователь не теряет доступ к критичным деталям в дороге. | При отсутствии сети открываются ранее сохраненные данные текущей поездки: дни, места, рейсы, жилье, заметки и чеклисты, если чеклисты включены; приложение явно отделяет сохраненные данные от действий, которым нужен интернет. | Draft |
| FR-019 | Пользователь может настроить простое напоминание для рейса, жилья или события, если это не блокирует основной сценарий. | Should | Пользователь может не пропустить важный момент поездки. | Напоминание создается для выбранного времени; его можно изменить или удалить; если системные уведомления недоступны, пользователь получает понятное состояние без потери данных события. | Draft |
| FR-020 | Пользователь может заранее загрузить офлайн-карту области поездки. | Must | Карта поездки остается доступной без интернета. | Пользователь может выбрать область или поездку для загрузки карты; приложение показывает статус загрузки; после отключения сети сохраненная карта открывается и показывает сохраненные точки поездки; если офлайн-маршрутизация не поддержана, интерфейс не обещает построение маршрута без сети. | Draft |

## Explicitly Outside MVP Functional Scope

| ID | Requirement | Priority | Reason | Status |
| --- | --- | --- | --- | --- |
| FR-L-001 | LLM-рекомендации, генерация маршрутов или списков. | Later | Сначала нужно проверить базовую ручную агрегацию. | Draft |
| FR-L-002 | Автоматический импорт рейсов, бронирований, писем, PDF или календарей. | Later | MVP хранит данные, введенные пользователем вручную. | Draft |
| FR-L-003 | Live flight tracking, задержки, gate alerts и disruption support. | Later | Это отдельная глубокая операционная область. | Draft |
| FR-L-004 | Автоматическая оптимизация маршрута и собственная маршрутизация. | Later | MVP показывает порядок и карту, а навигацию отдает внешним картам. | Draft |
| FR-L-005 | Совместное редактирование, роли доступа и права. | Later | MVP проверяет личный сценарий. | Draft |
| FR-L-006 | Покупка билетов, бронирование жилья и платежи. | Later | MVP не заменяет booking-сервисы. | Draft |
| FR-L-007 | Офлайн-маршрутизация, если выбранный провайдер не поддерживает ее в рамках MVP. | Later | MVP обязан показывать загруженную офлайн-карту, но построение маршрута без сети требует отдельной проверки провайдера. | Draft |

## Non-Functional Requirements

| ID | Requirement | Priority | Acceptance criteria | Status |
| --- | --- | --- | --- | --- |
| NFR-001 | Основные сценарии должны быть удобны на мобильном экране. | Must | Создание поездки, добавление места, открытие текущего дня, жилья, рейса, заметок и включенного чеклиста выполняются без горизонтальной прокрутки и без обязательного десктопного интерфейса. | Draft |
| NFR-002 | Ручной ввод должен быть быстрым и терпимым к неполным данным. | Must | Для места, рейса и жилья минимально необходимое число обязательных полей не блокирует сохранение полезной черновой записи; необязательные поля можно заполнить позже. | Draft |
| NFR-003 | Основная информация текущей поездки должна открываться быстро. | Must | При нормальной сети основной экран поездки и текущий день открываются без заметной задержки для пользователя; тяжелые вторичные данные не блокируют чтение сохраненного плана. | Draft |
| NFR-004 | Потеря сети не должна приводить к потере уже сохраненного пользовательского ввода. | Must | Если сохранение не завершено из-за сети, пользователь видит понятное состояние ошибки или повтора; ранее сохраненные данные остаются доступными. | Draft |
| NFR-005 | Персональные данные поездки не должны попадать в диагностические логи в открытом виде. | Must | Логи не содержат номера брони, контакты жилья, заметки пользователя и полные детали рейсов без явной технической необходимости и защиты. | Draft |
| NFR-006 | Первая версия должна поддерживать русский язык пользовательского интерфейса. | Must | Все основные пользовательские тексты MVP-сценариев доступны на русском языке; смешение языков в пользовательском UI не блокирует выполнение сценария только для технических имен или прототипных заглушек. | Draft |
| NFR-007 | Состояния ошибок и пустые состояния должны объяснять следующий доступный шаг. | Must | Для пустой поездки, пустого дня, отсутствия координат, недоступной внешней навигации и слабого интернета есть понятное сообщение или действие. | Draft |
| NFR-008 | MVP не должен обещать функциональность, которая находится outside MVP. | Must | В интерфейсе и требованиях нет формулировок, подразумевающих автоматический импорт, live flight tracking, route optimization, booking, collaboration, LLM или офлайн-маршрутизацию без подтвержденной поддержки провайдера. | Draft |
| NFR-009 | Офлайн-карта должна быть явно подготовлена до поездки. | Must | Пользователь видит, загружена ли карта области поездки; без предварительной загрузки приложение не обещает работу карты без сети. | Draft |
