## UC-001 Create Trip

Primary actor: Traveler

Goal: создать поездку.

Main flow:

1. Пользователь нажимает "Создать поездку".
2. Вводит название.
3. Указывает даты, если они известны.
4. Сохраняет поездку.

Open questions:

- Какие поля обязательны?
- Нужно ли указывать страну или город?

## UC-002 Add Place To Map

Primary actor: Traveler

Goal: добавить место в поездку.

Main flow:

1. Пользователь вводит название места.
2. Приложение показывает результаты поиска.
3. Пользователь выбирает место.
4. Приложение добавляет точку на карту.

Exceptions:

- Место не найдено.
- Нет интернета.
- Пользователь хочет добавить точку вручную.

MVP notes:

- Если поиска нет из-за слабого интернета, пользователь может сохранить место вручную по названию и адресу текстом.
- Приложение не строит собственный маршрут; для навигации используется внешнее картографическое приложение.

## UC-003 Plan Day Route

Primary actor: Traveler

Goal: распределить места по дню и посмотреть маршрут.

Main flow:

1. Пользователь открывает день поездки.
2. Добавляет места в план дня.
3. Меняет порядок мест.
4. Смотрит маршрут на карте.

MVP notes:

- "Маршрут" в MVP означает порядок точек дня и их отображение на карте, а не автоматическую оптимизацию.
- Пользователь может открыть конкретное место во внешних картах для навигации.

## UC-004 Add Hotel Booking

Primary actor: Traveler

Goal: сохранить информацию о жилье.

Main flow:

1. Пользователь добавляет отель или другое жилье.
2. Указывает адрес, даты, время заселения и выселения.
3. Добавляет номер брони и заметки при необходимости.
4. Сохраняет бронь.

## UC-005 Add Flight

Primary actor: Traveler

Goal: сохранить информацию о рейсе.

Main flow:

1. Пользователь вводит номер рейса.
2. Пользователь вручную указывает дату, время, аэропорты и при необходимости терминал/гейт как текст.
3. Пользователь добавляет номер брони и заметки при необходимости.
4. Сохраняет рейс.

MVP note:

Автозаполнение, live flight tracking, задержки и gate alerts не входят в MVP. Рейс хранит стабильные данные, которые пользователь ввел вручную.

## UC-006 Use Main Trip Screen Before Trip

Primary actor: Traveler

Goal: подготовить поездку через один основной мобильный экран.

Main flow:

1. Пользователь открывает поездку до даты начала.
2. Приложение показывает режим подготовки: дни поездки, карту мест и быстрые действия.
3. Пользователь открывает нужный день.
4. Добавляет или переставляет места, рейсы, жилье, заметки и чеклисты.
5. Проверяет, что план дня и точки на карте соответствуют друг другу.

MVP notes:

- Главный экран не должен быть маркетинговым или декоративным обзором.
- До поездки приоритет у структуры дней и заполнения пробелов, а не у уведомлений или рекомендаций.

## UC-007 Use Main Trip Screen During Trip

Primary actor: Traveler

Goal: быстро понять, что делать сейчас и куда идти дальше.

Main flow:

1. Пользователь открывает поездку во время дат поездки.
2. Приложение открывает текущий день или ближайший релевантный день.
3. Пользователь видит ближайший следующий пункт, план дня и компактную карту.
4. Пользователь одним тапом открывает навигацию к месту или жилью во внешних картах.
5. Пользователь одним тапом открывает жилье, рейсы, заметки или чеклист.

Exceptions:

- Даты поездки неизвестны или не совпадают с текущей датой.
- На текущий день нет плана.
- Внешняя карта недоступна.

MVP notes:

- Во время поездки главный экран должен минимизировать чтение, поиск и глубокую навигацию.
- Если автоматическое определение "Сегодня" не сработало, пользователь должен вручную выбрать день.

## UC-008 Access Saved Trip Details With Weak Internet

Primary actor: Traveler

Goal: прочитать критичные сохраненные данные при слабом интернете.

Main flow:

1. Пользователь открывает текущую поездку при слабом интернете или без сети.
2. Приложение показывает сохраненные детали поездки, если они были кэшированы.
3. Пользователь открывает сегодняшний план, жилье, рейсы, заметки или чеклист.
4. Приложение явно показывает, что поиск новых мест, обновления и внешняя навигация могут требовать интернет.

MVP notes:

- Офлайн-доступ в MVP не означает офлайн-карты или офлайн-маршрутизацию.
- Минимальная ценность офлайн-режима - чтение сохраненных текстовых деталей текущей поездки.

## UC-009 Quick Manual Edit During Trip

Primary actor: Traveler

Goal: быстро поправить план без сложного редактирования.

Main flow:

1. Пользователь открывает текущий день.
2. Выбирает существующий пункт или нажимает добавление.
3. Меняет время, заметку, порядок или добавляет новый ручной пункт.
4. Сохраняет изменение и возвращается на план дня.

MVP notes:

- Быстрая правка нужна, потому что реальные поездки меняются на месте.
- Не требуется совместное редактирование, история изменений или автоматическая перестройка маршрута.

## Critical One-Tap Travel Access

Во время поездки из главного экрана в один тап должны открываться:

- текущий день;
- ближайший следующий пункт;
- внешняя навигация к месту или жилью;
- жилье;
- рейсы;
- заметки;
- чеклист;
- сохраненные офлайн-детали, если кэширование реализовано.

## UX Risks And Open Questions

Risks:

- Слишком широкий главный экран может стать еще одним местом, где пользователь ищет информацию.
- Слишком большой обязательный ввод ухудшит ручную агрегацию.
- Непонятная формулировка офлайн-доступа создаст ожидание офлайн-карт.
- Автоматический режим "Сегодня" может ошибиться для поездок без дат или с неполным планом.

Open questions:

- Подтвердить главный экран "Сегодня / Дни / Карта" как MVP-структуру.
- Решить, какой объем данных кэшируется без сети.
- Решить, входят ли напоминания в MVP или остаются позже.
- Уточнить обязательные поля для рейса и жилья.
