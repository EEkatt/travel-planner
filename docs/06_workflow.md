# Процесс разработки

## Цель

Описать рабочий процесс от идеи до реализации и релиза с учетом будущей мультиагентной системы.

## Этапы

### 1. Идея

Артефакты:

- `docs/00_idea.md`.

Результат:

- понятна проблема;
- понятна аудитория;
- понятна ценность продукта;
- есть открытые вопросы.

### 2. Продуктовое ТЗ

Артефакты:

- `docs/01_product_requirements.md`;
- `specs/mvp.md`.

Результат:

- описаны роли;
- описаны ключевые сценарии;
- определены границы MVP;
- требования имеют приоритеты.

### 3. Техническое ТЗ

Артефакты:

- `docs/02_technical_requirements.md`;
- `docs/03_architecture.md`.

Результат:

- выбран стек;
- описана архитектура;
- определены данные, интеграции, безопасность и деплой.

### 4. План разработки

Артефакты:

- `specs/backlog.md`.

Результат:

- требования разложены на задачи;
- задачи имеют приоритет;
- понятен порядок реализации.

### 5. Реализация

Артефакты:

- `app/`;
- тесты;
- документация запуска.

Результат:

- реализованы задачи;
- тесты проходят;
- документация обновлена.

### 6. Проверка

Артефакты:

- QA-чеклист;
- отчеты агентов;
- результаты тестов.

Результат:

- ключевые сценарии проверены;
- найденные дефекты заведены в бэклог;
- решение готово к следующему этапу.

## Правила изменения документов

- Документы должны меняться маленькими правками.
- Если меняется важное решение, добавлять запись в `docs/07_decisions.md`.
- Если появляется вопрос без ответа, добавлять его в раздел `Открытые вопросы`.
- Если требование становится неактуальным, не удалять сразу, а переносить в соответствующий раздел с причиной.

## Definition of Ready

Задача готова к разработке, если:

- понятна пользовательская или техническая цель;
- описан ожидаемый результат;
- известны ограничения;
- понятен способ проверки;
- нет блокирующих открытых вопросов.

## Definition of Done

Задача завершена, если:

- реализация соответствует требованию;
- добавлены или обновлены нужные тесты;
- локальные проверки проходят;
- документация обновлена;
- нет известных критичных дефектов.
