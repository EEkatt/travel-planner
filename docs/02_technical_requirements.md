# Технические требования

> Archived / legacy draft. Kept for historical context only.
> Current architecture and technical decisions are in `architecture/`.

## Статус

Черновик. Требует выбора платформы и стека.

## Тип приложения

Основной целевой формат - мобильное приложение. Web-версия может появиться позже для удобного планирования из дома, но первый продукт должен быть удобен на телефоне.

Нужно выбрать технический путь:

- native iOS;
- cross-platform mobile;
- mobile-first web/PWA как быстрый прототип;
- hybrid-подход.

Возможные варианты:

- web app;
- mobile app;
- desktop app;
- Telegram bot;
- API-first service;
- hybrid.

## Данные

Предварительные сущности:

- User.
- Trip.
- Place / Map Point.
- Route / Ordered Point List.
- Day Plan.
- Flight.
- Hotel Booking.
- Note.
- Checklist / Checklist Item.
- Reminder.
- Attachment, возможно позже.
- Budget / Expense, позже.

Чувствительные данные:

- данные рейсов;
- номера бронирований;
- адреса отелей;
- личные заметки;
- потенциально документы и PDF, если появятся вложения.

## Безопасность

- Нужно решить, нужна ли авторизация в MVP.
- Нельзя логировать номера бронирований, персональные заметки и потенциальные документы.
- Платежи не входят в MVP.
- Если продукт выйдет за пределы личного использования, потребуется отдельно рассмотреть требования к персональным данным.
- Не рекомендуется хранить паспортные данные в ранних версиях.
- Номера бронирований и билеты хранить можно, но нужно продумать локальное хранение, резервные копии и доступ.

## Производительность

Приложение должно быстро открывать план поездки, карту, жилье, рейсы и заметки во время поездки. Долгие операции допустимы при планировании и перестроении маршрута, но не при просмотре текущего дня.

## Наблюдаемость

Для MVP достаточно минимального логирования ошибок. Нельзя логировать персональные данные, номера броней, заметки и содержимое вложений.

Нужно определить:

- логирование;
- метрики;
- алерты;
- error tracking.

## Тестирование

Минимальный набор:

- unit tests для модели данных и бизнес-логики;
- integration tests для API поездок, рейсов, отелей и заметок;
- e2e tests для ключевого сценария: создать поездку, добавить точку, рейс, отель и заметку;
- ручной чеклист MVP перед реальной поездкой.
