# MAP-01 Map UX Flow

Task ID: TASK-20260704-020
Agent: ux_analyst
Date: 2026-07-04
Status: Ready for qa_engineer and product_analyst review

## Summary

The MVP map should behave as a mobile trip workspace, not as a full navigation product. The screen should let the traveler view saved Georgia trip points, switch between all points, no-day points, and one selected route day, add points through online search or map tap, assign or clear day membership, reorder a day route through cards below the map, and open Yandex Maps only as a point-level fallback.

Preserved decisions:

- MVP geography is Georgia.
- Points without a day are neutral gray.
- Points assigned to a route day are red.
- Day mode shows numbered points and a route line.
- Reordering is done through cards below the map, not by dragging pins.
- Concrete place search is in scope; suggestions/autocomplete only if the production provider permits it.
- Yandex Maps handoff is a fallback, not the primary route experience.
- Do not promise offline search, geocoding, routing, route optimization, traffic, or turn-by-turn navigation without provider proof.

## Recommended Map Screen Structure

Use one mobile-first `Map` tab inside the existing `Today / Days / Map` trip structure.

1. Trip map status header
   - Title: `Trip map`.
   - Offline map status: not downloaded, downloading, downloaded, failed, outside downloaded area.
   - Saved details status: saved trip lists/details remain available even when map/search fail.
   - Primary action: `Download Georgia map` or `Retry download` when online and supported.

2. Map mode and filter controls
   - Segmented filters: `All`, `No day`, `Day 1`, `Day 2`, etc.
   - `All`: shows every coordinate-backed saved point.
   - `No day`: shows only unscheduled coordinate-backed points in gray.
   - One day: shows only that day's coordinate-backed route points in red, numbered by card order, with a route line between them.
   - Keep zoom/pan native to the map provider. Avoid separate route-edit gestures on pins for MVP.

3. Map canvas
   - Shows downloaded/online map area, pins, selected-day route line, and concise map state banners.
   - If a point lacks coordinates, exclude it from pins but keep it in the list below.
   - Route line copy must indicate planned order/context, not turn-by-turn navigation.

4. Add/search panel
   - Online search by explicit user action.
   - Suggestions/autocomplete only after provider approval.
   - Manual/map-tap add remains reachable when search is unavailable, returns no results, or the device is offline.
   - User chooses `No day` or a concrete day before saving.

5. Cards below map
   - In `All` and `No day`: show saved point cards relevant to the filter.
   - In one-day mode: show route cards in the exact order used for map numbering and route line.
   - Cards are the editing surface: assign day, clear day, reorder, open details, open Yandex Maps fallback.
   - Cards for no-coordinate places stay visible with `Not shown on map yet`.

## Critical User Flows

### View All Points

1. User opens `Map`.
2. Filter defaults to `All` unless returning from a selected day.
3. Map shows all coordinate-backed saved points in Georgia.
4. No-day points are gray; day-assigned points are red.
5. Below the map, cards list all saved points matching the current trip, including a separate no-coordinate section.
6. No route line is shown in `All` mode because multiple days may be mixed.

Acceptance note: all coordinate-backed points render; no-coordinate points are not lost and remain visible in cards/lists.

### View No-Day Points

1. User selects `No day`.
2. Map shows only coordinate-backed points with no day assignment.
3. Pins are gray and unnumbered, or numbered only as list indices if the provider requires labels; they must not imply route order.
4. Cards show unscheduled places and actions to assign each place to a day.
5. If there are no no-day points, show an empty state with `Add place` and `Search online` when online.

Acceptance note: no-day points never appear red and are not included in a route line.

### View One Day Route

1. User selects a concrete day.
2. Map shows only that day's coordinate-backed places.
3. Pins are red and numbered according to card order.
4. A route line connects points in the same order.
5. Cards below the map show the ordered route list.
6. Reordering cards immediately updates card order, pin numbers, and route line sequence.
7. Places for that day without coordinates appear in the cards with a missing-coordinate state and are excluded from the map/line.

Acceptance note: the route line represents planned order only. UI copy must not call it offline routing, navigation, optimization, or travel-time estimation.

### Map-Tap Point Creation

1. User taps the map inside the supported Georgia/downloaded area.
2. App records coordinates and opens a compact save sheet or inline add panel.
3. User enters title, optional address/note, and chooses `No day` or a day.
4. Save creates the point with source `manual map tap`.
5. If saved as `No day`, the point appears gray in `All` and `No day`.
6. If saved to a day, the point appears red in that day and is appended to the end of that day's card order by default.

Edge behavior:

- If tap is outside MVP area, show outside-area state and do not create a point until user confirms manual text entry or chooses a valid location.
- If coordinates cannot be captured, keep manual text entry available.

### Search Result Point Creation

1. User opens search in the map screen.
2. User enters a concrete place or landmark, for example `Narikala Fortress`.
3. User triggers search explicitly. Autocomplete is allowed only with an approved production provider.
4. Results show title, address/description, and enough context to avoid adding the wrong place.
5. User selects a result, chooses `No day` or a day, and saves.
6. Save creates the point with source `search result`, title/address, and provider-normalized coordinates.
7. The saved point appears in the relevant filter and card list.

Fallbacks:

- Offline, provider failure, and no results all keep `Add manually` available.
- Public Nominatim must not be used for production autocomplete.

### Assign Or Clear Day

1. User opens a point card or point detail.
2. User chooses `Assign to day` or `Clear day`.
3. Assigning to a day changes the point from gray/no-day to red/day route and appends it to the end of that day's route order unless the user chooses a position.
4. Clearing a day removes the point from the route order and route line, then shows it as gray/no-day.
5. No-coordinate points can be assigned to a day, but they stay off the map until coordinates are added.

Acceptance note: day assignment is a data change independent from coordinate availability.

### Reorder Cards

1. User selects one concrete day.
2. Cards below the map become reorderable.
3. User moves a card up/down or drags it within the list, depending on final implementation.
4. The app updates route order.
5. Pin numbers and route line update from the same ordered list.
6. User remains in the selected day filter after reorder.

MVP recommendation: provide explicit move controls or a proven accessible drag pattern. Do not require pin dragging on the map.

### Open Yandex Maps Fallback

1. User opens a saved point card or detail.
2. If the point has coordinates or a usable address, show `Open in Yandex Maps`.
3. Tapping attempts to open Yandex Maps with coordinates preferred over free-text address.
4. If Yandex Maps is unavailable, show a concise failure state and keep address/coordinates visible.
5. If the point has neither coordinates nor address, disable the action with `Add address or location first`.

Acceptance note: this is a fallback for point-level navigation. It must not replace in-app map viewing of saved points and planned day route context.

## Empty, Error, Offline, And Failure States

| State | Trigger | User-facing behavior | Primary action | Fallback |
| --- | --- | --- | --- | --- |
| Empty trip map | No saved points in trip | Show empty map/list state: no saved places yet | Add place | Continue to days/notes |
| Empty no-day filter | No points with `No day` | Explain that all places are assigned or none exist | Add no-day place | Switch to all points |
| Empty day route | Selected day has no places | Show day map empty state | Add place to this day | Open day plan |
| No-coordinate points | Saved points lack coordinates | Show in `Not shown on map yet` card section | Add location/edit address | Keep item in plan/list |
| Offline, map downloaded | Network unavailable and Georgia area is downloaded | Open downloaded map with saved points/routes; mark online actions unavailable | Use saved map | Read saved lists/details |
| Offline, map not downloaded | Network unavailable and no offline area exists | Explain offline map is not downloaded | Retry/download when online | Use saved lists/details |
| Search offline | User tries search without network | Search disabled or returns offline state | Add manually | Save title/address/note without coordinates |
| No search results | Provider returns empty result set | Show no-results state | Refine search | Add manually |
| Search provider failure | Timeout, quota, API error, provider unavailable | Show provider failure without losing query | Retry | Add manually |
| Map provider failure | Map tiles/SDK fail online or offline | Show map unavailable state | Retry map | Use cards/lists as source of truth |
| Outside MVP area | User searches/taps outside Georgia or outside downloaded pack | Explain area is outside MVP/downloaded map | Save as manual text if needed | Choose valid Georgia location |
| Outside downloaded area | User pans/taps outside downloaded area while offline | Show boundary/area warning | Return to downloaded area | Use saved details |
| Point outside Georgia | Search result coordinates are outside MVP country | Warn before saving; default recommendation is not to save for MVP trip map | Search again | Save manual note only if product allows |
| Yandex Maps unavailable | Deep link/app open fails | Show fallback failure | Retry/open web if approved | Show/copy address or coordinates |
| Missing navigation target | Point has no address and no coordinates | Disable external maps action | Add location/address | Keep point details visible |

Copy principles:

- Say what still works first: saved details, downloaded map, saved points, manual entry.
- Name unavailable capability narrowly: search, map loading, offline map, external map handoff.
- Avoid broad claims such as `works offline`.
- Use `planned route/order` rather than `navigation`, `routing`, `optimized route`, or `travel time`.

## UX Risks

- Users may expect offline search, geocoding, routing, or turn-by-turn navigation if offline map copy is too broad.
- A map-first failure state can hide the reliable source of truth: saved day cards and lists.
- Missing-coordinate places can feel lost unless they remain visible in cards and day plans.
- Numbered pins in `All` or `No day` mode could falsely imply route order; numbering should be reserved for selected day mode.
- Route line styling may be interpreted as road-snapped navigation; copy and visual treatment should indicate planned order only.
- Reordering must be comfortable on mobile. Drag-only reorder can be fragile if accessibility and touch conflicts are not handled.
- Provider terms may block client-side suggestions/autocomplete, requiring explicit search-only UX.
- Yandex Maps fallback can become over-prominent and make the app feel like a launcher instead of a trip workspace.
- Whole-country Georgia offline pack feasibility is not proven; UX must handle approved regional/city pack fallback if owner accepts it later.

## Unresolved Decisions

- Provider decision: which production map/search/offline provider is allowed by terms, pricing, attribution, storage rights, API key model, and mobile SDK behavior.
- Offline pack model: whole Georgia as one pack versus owner-approved Georgia regions/cities if whole-country is impractical.
- Search suggestions: whether the selected provider permits autocomplete for production use.
- Outside-area policy: whether the app should block saving outside-Georgia coordinates or allow them as non-MVP/manual notes.
- Reorder interaction: explicit up/down buttons, drag handle, or both.
- Day route line: straight planning line versus provider-rendered route geometry if online routing becomes available later.
- Yandex Maps fallback details: app-only deep link, web fallback, copy-address fallback, and priority when multiple map apps exist.
- Coordinate editing: whether MVP includes edit-on-map for an existing point or only add/replace location.

## Acceptance Notes For Later QA

QA should validate the map UX with deterministic fixtures before provider integration is treated as complete:

- All-points filter shows every coordinate-backed saved point and no route line.
- No-day filter shows only no-day coordinate-backed points in gray and keeps assign-day actions visible.
- Selected-day filter shows only that day's coordinate-backed points in red, with numbering and a route line matching card order.
- Reordering day cards updates card order, pin numbers, and route line order from the same source.
- Map-tap save creates a point with coordinates, title, source, and chosen day/no-day state.
- Search-result save creates a point with normalized title/address/coordinates and chosen day/no-day state.
- Assigning a day changes color/category and route inclusion; clearing day removes route inclusion and makes the point gray.
- No-coordinate points remain in cards/lists and never render as map pins.
- Offline with downloaded map shows saved points/routes but does not expose search/geocoding/routing promises.
- Offline without downloaded map leaves saved trip lists/details usable and clearly explains the missing map.
- Search no-results, offline, and provider-failure states all offer manual save.
- Outside Georgia or outside downloaded-area states are visible and do not silently create misleading pins.
- Provider map failure does not crash or hide saved cards/lists.
- Yandex Maps opens only when address or coordinates exist; missing target disables the action; handoff failure leaves saved address/coordinates readable.
- UI copy avoids promises of offline search, offline geocoding, route optimization, traffic, turn-by-turn navigation, and guaranteed external navigation.

## Prototype Context Read

Current `app/mobile/App.tsx` already demonstrates the intended direction: `Today / Days / Map`, map filters, explicit online search, map-click point creation on web, no-day/day assignment, visible and hidden point lists, point colors, and a selected-day route line in the web Leaflet prototype. This report treats that as prototype context only; it does not consider current code proof of native/offline/provider behavior.
