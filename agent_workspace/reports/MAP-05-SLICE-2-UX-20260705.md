# MAP-05 Slice 2 UX: One-Flow Add Place Correction

Date: 2026-07-05
Role: ux_analyst
Status: Ready for lead review

## Scope

This report defines the corrected map add-place UX for the current mobile prototype. It addresses owner feedback that the map currently has two competing add/search surfaces and requires pressing `Find` before options appear.

The MVP/prototype country scope is Georgia. Suggestions in this slice are local/mock Georgia fixtures only. This report does not approve production autocomplete, provider-backed autocomplete, public Nominatim autocomplete, offline search, offline geocoding, routing, navigation, optimization, traffic, ETA, or live rerouting.

## Recommended One-Flow Map Screen Behavior

The map screen should expose one obvious `Add place` flow.

Recommended structure:

1. Keep the map, day filters, map status, and saved point list.
2. Replace the separate `Search place online` panel and `Add point by click` panel with one `Add place` entry point.
3. Opening `Add place` shows one bottom-sheet/panel on the same screen.
4. The sheet contains:
   - one text input for place name/address;
   - local/mock Georgia suggestions that update while typing;
   - one day assignment control with `No day`, `Day 1`, `Day 2`, etc.;
   - one manual/map-tap fallback area inside the same sheet;
   - one save action that saves the currently selected suggestion or manual/map-tap draft.
5. The user never has to choose between separate search and map-click panels.
6. The user never has to press `Find` before seeing local/mock suggestions.

The primary map screen can show a compact `Add place` button near the map/list controls. Empty states for `All`, `No day`, and selected day should use the same `Add place` action, not separate search/manual actions.

## Add-Place Interaction States

### Closed

- Map and saved place list are visible.
- `Add place` is the only add/search entry point.
- If a day filter is selected, opening the flow preselects that day. If `All` or `No day` is selected, opening the flow preselects `No day`.

### Open, Empty Input

- The input is focused.
- The day picker is visible.
- No remote request is made.
- The sheet may show a small set of featured local/mock Georgia fixtures, or an empty suggestion area with manual/map-tap options. Either is acceptable.
- The manual/map-tap fallback is visible in the same sheet.

### Typing

- Suggestions update as the user types.
- Results come only from the local/mock Georgia fixture list.
- Suggestions are explicitly scoped to Georgia fixtures and should use Georgia addresses/labels.
- No `Find` button is required for local/mock suggestions.
- If a visible search/submit button remains, it must be secondary and must not be required for suggestions to appear.

### Suggestion Selected

- Selecting a suggestion fills a pending draft with title, address, latitude, longitude, `countryCode = GE`, and `source = search_result` or equivalent mock-search source.
- The selected suggestion is highlighted in the sheet.
- The map may preview the selected coordinate with a temporary, unsaved marker.
- The day picker remains editable before save.
- Save creates one point and closes or resets the sheet.

### No Local Suggestion Match

- The query is preserved.
- Show a no-results state such as `No Georgia fixture matches this text in the prototype`.
- Offer manual text save and map-tap coordinate fallback in the same sheet.
- Do not imply that production search was attempted.
- Do not call public Nominatim or any production provider as autocomplete.

### Map Tap Captured

- If the user taps the map while the add-place sheet is open, the sheet changes to a map-tap draft state.
- The selected coordinates are shown in the sheet.
- If the text input already has a value, keep it as the proposed title.
- If the text input is empty, require the user to enter a title before save.
- The day picker remains editable.
- Save creates a point with `source = manual_map_tap`, the tapped coordinates, `countryCode = GE` only when the coordinate is classified inside Georgia, and the selected day assignment.

### Manual Text Draft

- The user can save a manual text-only place from the same sheet when no suggestion is selected and no coordinate has been tapped.
- Manual text-only save creates a list/card point with `source = manual_text`, `coordinates = null`, and no map pin.
- Manual text-only save is allowed for notes such as `Dinner reservation` or `Cafe idea without location`.
- The user should understand it will appear in the list, not on the map, until coordinates are added in a later scope.

### Outside Georgia Coordinate

- If a tapped coordinate or selected fixture is outside Georgia, do not save a coordinate-backed point by default.
- Show a scoped warning: `This place is outside the Georgia MVP map`.
- Offer search/edit again and manual note-only save only if the implementation already supports text-only points.
- Do not persist a temporary pin, route point, or coordinate-backed place outside Georgia.

## Typing Suggestion Behavior For Local/Mock Georgia Fixtures

For this slice, suggestions should be deterministic local/mock data. The fixture set can be small and should include Georgia places already used by map requirements:

| Fixture | Address/description | Coordinates |
| --- | --- | --- |
| Narikala Fortress | Tbilisi, Georgia | 41.68860, 44.80860 |
| Rike Park | Tbilisi, Georgia | 41.69370, 44.81060 |
| Freedom Square | Tbilisi, Georgia | 41.69300, 44.80150 |
| Sulfur Baths | Abanotubani, Tbilisi, Georgia | 41.68790, 44.81120 |
| Svetitskhoveli Cathedral | Mtskheta, Georgia | 41.84180, 44.72100 |
| Batumi Boulevard | Batumi, Georgia | 41.65090, 41.63600 |

Matching behavior:

- Normalize case.
- Trim leading/trailing whitespace.
- Match against title and address/description.
- Show suggestions after the first non-empty character.
- Limit visible suggestions to a compact mobile-safe count, for example 5.
- Keep all suggestion records country-scoped with `countryCode = GE`.
- If the app needs an outside-country negative fixture for QA, it must not appear in normal Georgia-scoped suggestions.

Copy should make the prototype boundary clear without overexplaining. Acceptable examples:

- `Georgia prototype suggestions`
- `Local Georgia fixtures`
- `No Georgia fixture matches this text`

Avoid copy that implies a production provider or broad live search, such as `Search all places`, `Autocomplete from map provider`, `Worldwide results`, or `Powered by Nominatim`.

## Manual/Map-Tap Fallback Inside The Same Flow

Manual and map-tap fallback must not be a second add surface.

Inside the `Add place` sheet:

- Provide a `Use map tap` or equivalent mode that tells the user to tap the map.
- Keep the same text input and day picker.
- After the tap, show the selected coordinates in the sheet.
- Allow replacing the tapped coordinate by tapping the map again while the sheet remains open.
- Allow clearing the tapped coordinate to return to text/suggestion mode.
- Manual text-only save remains in the same sheet when no coordinate is selected.

Recommended save rules:

- Selected local Georgia suggestion: title can be accepted as-is; save enabled.
- Map-tap draft: title required; Georgia coordinate required for coordinate-backed save.
- Manual text-only draft: title required; coordinates remain null; no pin.
- Empty input with no selected suggestion and no map tap: save disabled.

## Day Assignment Behavior

Day assignment is part of the same add-place flow and appears before saving.

Defaults:

- If current map filter is `Day 1`, `Day 2`, etc., preselect that day.
- If current map filter is `No day`, preselect `No day`.
- If current map filter is `All`, preselect `No day`.

Saving:

- `No day` creates a gray unnumbered pin when the point has coordinates.
- A selected day creates a red day point and appends it to the end of that day's card order.
- The appended point receives the next route order for that day.
- The selected-day route line uses day card order and skips no-coordinate points without renumbering unrelated records.
- Manual text-only points assigned to a day appear in the day card list at the next order but do not render as pins.

After save:

- If saved to `No day`, remain on `All` or switch to `No day` only if that was the active filter before opening.
- If saved to a selected day, keep or switch to that day so the user can see the new route/card result.
- The saved card/list is always the source of truth. Map pins are only rendered for coordinate-backed points.

## Acceptance Checks For Mobile Implementation

The mobile implementation should pass these checks:

- There is exactly one visible add/search flow on the map screen.
- The previous separate search panel and map-click add panel are removed or merged into the single `Add place` sheet/panel.
- Typing in the add-place input shows local/mock Georgia suggestions without pressing `Find`.
- Suggestions are deterministic local fixtures; no network request is made for autocomplete.
- Public Nominatim is not used for autocomplete.
- Suggestion records are scoped to Georgia and carry `countryCode = GE`.
- Selecting a suggestion lets the user save it as `No day` or a selected day.
- A no-day coordinate-backed save appears as a gray unnumbered pin in `All` and `No day`.
- A day-assigned coordinate-backed save appears as a red numbered pin in that day and appends to the day route order.
- Map tap is available from inside the same add-place flow, not as a separate panel.
- Tapping inside Georgia can create a coordinate-backed manual point after title and day assignment are set.
- Manual text-only save is available inside the same flow and creates a card/list item without a pin.
- Outside-Georgia coordinates are not silently saved as coordinate-backed points.
- Empty, no-result, and provider/prototype-boundary states preserve the user's typed text.
- Offline copy does not promise offline search, offline geocoding, offline routing, navigation, optimization, traffic, ETA, or live rerouting.
- The UI remains usable on a narrow mobile viewport: input, suggestion rows, day chips, coordinate preview, and save action do not overlap or require horizontal scrolling.

## Explicit Non-Goals

- No production autocomplete provider.
- No public Nominatim autocomplete.
- No provider keys.
- No broad live place search claim.
- No worldwide or multi-country suggestions.
- No offline search.
- No offline geocoding.
- No offline routing or turn-by-turn navigation.
- No route optimization.
- No traffic, ETA, or live rerouting.
- No proof of whole-country Georgia offline map download.
- No native/offline map SDK proof.
- No persistence guarantee beyond the current prototype's existing behavior.

## Implementation Direction Summary

For MAP-05 Slice 2, the corrected behavior is: one `Add place` flow, one input, local/mock Georgia suggestions while typing, and manual/map-tap fallback inside the same sheet before saving to `No day` or a selected day.

This is intentionally prototype-safe. It demonstrates the owner's desired interaction without claiming production autocomplete or provider-backed search.
